# BranchGuard 产品简报

## 一句话定位

BranchGuard 是一个轻量 Git 冲突预检查工具，让小团队在真正合并前提前知道哪些分支会冲突、冲突在哪些文件、风险有多高。

## 问题背景

小团队的 Git 冲突问题通常不是“不知道怎么解决冲突”，而是“发现得太晚”。

常见场景：

- 多个人同时改同一块业务代码，到发版前才发现冲突。
- 新人、外包或临时协作成员不熟悉分支规范，频繁把分支拖到很久才合。
- 团队依赖 JetBrains、SourceTree、GitKraken 等工具处理冲突，但缺少一个提前预警的轻量流程。
- 命令行可以做到部分检测，但输出不面向团队协作，缺少冲突矩阵、风险分级和报告。

## 目标用户

### 核心用户

- 5-10 人研发小团队。
- 外包项目团队。
- 前后端并行开发、多人同时改页面或接口的团队。
- 新人多、Git 规范薄弱、合并经常拖到发版前的团队。

### 次级用户

- 使用多个 Git worktree 并行开发的个人开发者。
- 使用 AI coding agent 并行改代码的开发者。
- 想在 CI 里提前阻断高风险合并的技术负责人。

## 核心价值

### 对个人开发者

- 合并前提前知道会不会炸。
- 不需要打开重型 IDE 或 Git GUI。
- 不需要真的执行 merge 后再 abort。

### 对小团队

- 发版前减少临时救火。
- 技术负责人能看到分支冲突矩阵。
- 冲突责任更清楚，谁和谁的分支冲突一眼可见。

## 产品边界

第一阶段只做“预检查”，不做“自动解决冲突”。

做：

- 分支之间的冲突预检查。
- 冲突文件列表。
- 冲突数量统计。
- 风险等级。
- JSON 输出，便于接入 CI。
- 单仓库内分支冲突矩阵。

不做：

- 不替代 JetBrains / VS Code 的三栏冲突解决 UI。
- 不自动修改用户代码。
- 不做完整 Git 客户端。
- 不做云端代码托管。

## 差异化

现有工具通常解决的是“冲突发生后如何解决”，BranchGuard 解决的是“冲突发生前如何预警”。

关键差异：

- CLI first，一行命令可用。
- 无额外运行时依赖，尽量单文件分发。
- read-only，不改仓库。
- 输出面向团队，而不是只面向 Git 专家。
- 后续可以自然扩展到 GitHub Action、VS Code 插件、飞书/钉钉通知。

## 商业假设

免费版：

- 单次分支检查。
- 基础冲突文件输出。
- JSON 输出。

Pro 版或团队版：

- 全分支冲突矩阵。
- GitHub Action / GitLab CI 集成。
- 飞书/钉钉/企业微信通知。
- 每周冲突报告。
- 冲突责任人识别。
- 风险规则配置。
- 锁文件、schema、i18n、路由文件等高风险文件专项规则。

## 定价假设

早期面向国内小团队，先验证买断制：

- 个人 Pro：人民币 99-199 元买断。
- 小团队版：人民币 299-999 元买断或年费。
- 企业私有版：按需报价。

第一阶段不急着做支付系统。先用试用版 + 手动 license key 验证付费意愿。

## 成功指标

### MVP 成功

- 2-4 周内完成可用 CLI。
- 至少 20 个真实开发者试用。
- 至少 5 个用户主动反馈。
- 至少 1-3 个用户表达付费意愿。

### 早期增长

- GitHub star 100+。
- 每周真实活跃用户 20+。
- 至少 3 个团队在 CI 或日常合并前使用。

### 商业验证

- 30 天内产生第一笔收入。
- 有用户愿意为团队报告、CI 检查或通知功能付费。

## 主要风险

- 技术风险：不同 Git 版本、换行符、重命名、二进制文件、子模块等场景复杂。
- 产品风险：开发者认为命令行已经够用，不愿意为包装付费。
- 市场风险：Git GUI 或 AI IDE 可能加入类似能力。
- 定位风险：如果做成完整 Git 客户端，复杂度会失控。

## 风险应对

- 只做 read-only 预检查，不碰冲突解决。
- 先支持最常见的分支合并场景。
- 先做 CLI，压低开发和维护成本。
- 通过真实社区帖子和小团队访谈验证，不凭想象扩大需求。
