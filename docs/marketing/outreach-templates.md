## Tech Lead

> 我在做一个轻量 Git 冲突预警工具 BranchGuard，定位是给 5-20 人小团队在 PR 阶段提前发现冲突。  
> 它不会上传代码，也不会自动改分支，只用 `git merge-tree` 做只读检查，可以在 GitHub Action 里自动评论。  
> 如果你们最近有多分支并行开发，我想请你帮忙试一个仓库，重点看默认策略和报告是否有用。

## 3 天后跟进

> 前几天发你的 BranchGuard，有没有机会在仓库里跑一下？  
> 如果没时间也没事，我现在最想知道一个点：你觉得 Git 冲突预警应该出现在 PR 评论、群通知，还是每周报告里？

## 试用后追问

> 谢谢你试 BranchGuard。想问 4 个很具体的问题：  
> 1. 安装或 CI 接入有没有卡住？  
> 2. 报告里的冲突文件/风险等级有没有帮助？  
> 3. `fail-on-risk: high` 是否符合你们团队习惯？  
> 4. 如果继续用，你最希望下个版本补什么？
