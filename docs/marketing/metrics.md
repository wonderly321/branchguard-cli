## 合格信号

7 天内达到任意 2 个，就继续加速：

- 10 个真实开发者回复。
- 3 个真实仓库完成安装或 CI 接入。
- 1 个团队表示愿意持续使用。
- 1 个用户主动提 issue 或 PR。
- 有人明确说“这个能帮我们提前发现问题”。

## 风险信号

如果出现这些情况，要先调整定位：

- 大多数人以为它是 Git GUI。
- 大多数人期待自动解决冲突。
- 用户不知道应该在本地跑还是 CI 跑。
- GitHub Action 接入成本超过 10 分钟。
- 报告看完后不知道下一步该找谁。

## 反馈分类

记录每条反馈时，归到下面一类：

- 安装问题。
- CI 权限问题。
- 输出看不懂。
- 风险等级不准。
- 通知渠道缺失。
- 想要 GitLab / 企业微信 / VS Code。
- 愿意付费能力。

## 下一步判断

优先修阻碍首次使用的问题。只有当 3 个真实团队跑通后，再决定是否做：

- VS Code extension。
- 企业微信通知。
- 单文件二进制。
- 私有化团队版。
- 更完整的商业官网。
